# 똑띠체크 M1.3.9: 비행기 모드 오프라인 저장·재연결 업로드

## 구현
- IndexedDB 기존 reports에 추가로 sync_outbox를 생성(DB 버전 1 → 2): 보고서/사진/측정값 저장과 업로드 대기 표시를 **동일 트랜잭션**으로 기록합니다. 기존 reports는 보존됩니다.
- 네트워크 미연결 시 클라우드 요청을 보내지 않고 대기 상태를 표시합니다.
- 온라인 복구 시 인증과 권한을 재확인하고 Supabase 원격 revision과 마지막 확인 revision을 비교합니다. 서버가 바뀌지 않았을 때만 자동 업로드합니다. 충돌 시 자동 덮어쓰기 금지.
- 업로드가 성공한 후에만 대기 표시가 제거됩니다. 수정 중 새로운 기록이 생기면 삭제하지 않고 다음 전송을 기다립니다.
- Service Worker는 앱 화면과 정적 JS/CSS 등을 캐시합니다. Supabase DB 자료/인증 요청/API 응답은 서비스워커에 캐시하지 않습니다.
- 오프라인 재시작 시 기존 계정의 로그인 세션과 최근(7일) 인증된 권한을 로컬에서 확인해서 **기존 사용자만** 기기 내 점검을 계속하도록 합니다. 서버 변경 권한은 네트워크 복구 후 재검증됩니다. 로그인 이력이 없는 기기는 비행기 모드에서 새 로그인을 할 수 없습니다.

## 한계 및 주의
- 최초 1회는 온라인 상태에서 로그인하고 체크리스트 화면을 방문해 정적 파일 캐시가 설치되어야 합니다. 첫 설치 즉시 비행기 모드로 바꾸지 말고 정상 로드를 확인하세요.
- 휴대폰 Safari의 저장공간 관리나 브라우저 데이터 삭제로 IndexedDB/캐시가 삭제될 수 있습니다. JSON 백업 권장.
- 사진 포함 점검표는 현재 24MB 전송 제한이 유지됩니다. 매우 많은 사진에는 별도 Supabase Storage 설계가 필요합니다.
- 화면이 닫힌 동안 OS가 자동 백그라운드 업로드를 보장하지 않습니다. **네트워크 연결 후 해당 점검표를 한 번 열어야** 자동 업로드가 실행될 수 있습니다.
- 동일 계정의 `demo/current` 시험 데이터만 대상; 서로 다른 계정/현장 병합은 미구현. 다른 기기가 먼저 자료를 변경하면 자동 덮어쓰지 않고 충돌을 안내합니다.
- 클라우드 SQL/데이터/권한 변경 없음. ZIP에 포함된 SQL 파일을 재실행하지 마세요.

## 현장 시험 절차
1. 온라인에서 M1.3.9 업데이트 → 같은 계정으로 로그인 → 클라우드 저장 완료 확인 → JSON 백업.
2. 모바일 점검표를 연 상태에서 비행기 모드 → 사진 1장/점검 사유/측정값 입력 → `오프라인 · 이 기기에 저장됨 · 클라우드 업로드 대기` 확인.
3. 비행기 모드로 페이지 재방문하여 내용이 남았는지 확인(서비스워커 설치 후). 오프라인 페이지가 안 열리면 먼저 온라인에서 모든 리소스를 다시 로드.
4. 네트워크 켠 뒤 같은 점검표를 다시 열고 `클라우드 저장 완료` 확인.
5. 다른 PC에서 같은 계정으로 로그인 → 업데이트된 사진/사유/값 확인.
6. 반대 방향 테스트 및 두 기기 동시 편집 충돌 경고 확인.
