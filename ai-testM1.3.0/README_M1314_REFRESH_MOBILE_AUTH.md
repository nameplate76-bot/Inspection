# M1.3.14 — 새로고침 버튼 / 모바일 계정 확인 최적화

## 변경사항
- checklist.html 최상단 로그아웃 우측에 `↻ 새로고침` 버튼 추가.
- 버튼은 전체 페이지를 다시 불러오지 않고 클라우드의 최신 revision을 조회합니다. 서버 변경 시 문서를 수신하며 로컬 미전송분은 병합 절차를 거쳐 업로드합니다.
- 오프라인 / 클라우드 충돌 / 시간 초과인 경우 자동으로 서버 데이터를 덮어쓰지 않습니다.
- account.js 의 중복 인증·권한 조회를 합쳐 중복 네트워크 요청을 방지합니다. 20초 내 확인된 상태를 재활용하며 실제 서버 응답은 9초 제한합니다. 로그인 성공/상태 변경 시 강제 확인합니다.
- cloud-sync.js 에서 검증된 공용 계정·권한 정보를 사용해 중복 Auth getUser와 tt_users 쿼리를 제거합니다. 새로고침 공개 API refreshNow 추가.
- 기존 Supabase SQL, 사용자 권한, 점검 데이터, 사진, 점검표 템플릿은 수정하지 않았습니다.

## 테스트
1. 정상 로그인 상태에서 PC·모바일 양쪽 M1.3.14 표시 확인.
2. 모바일 점검표 사진 및 사유를 수정하고 **클라우드 저장 완료** 상태 확인.
3. PC 상단 `↻ 새로고침` → 최신 값 반영 확인.
4. PC 수정 후 모바일 새로고침, 동일하게 확인.
5. 비행기 모드에서 버튼 누르면 오프라인 안내가 나오며 로컬 기록이 유지되는지 확인.
6. 두 기기에서 서로 다른 내용을 동시에 편집했다면 원본/동기화 복구본을 확인.

## 제약
- 현재 `demo/current` 단일 시험용 점검표를 같은 계정으로 공유합니다.
- PC·모바일 실기기/Supabase 실서버 테스트는 배포 후 필요합니다.
- 통신이 느리거나 서버 권한 검증 실패 시 보호를 위해 편집 권한을 부여하지 않으며, 9초 후 지연 안내를 표시합니다.
