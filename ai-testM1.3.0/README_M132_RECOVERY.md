# 똑띠체크 M1.3.2 — 이전 자료 안전 복구

## 분석한 원인
- M1.2.8은 동일 GitHub Pages 출처의 IndexedDB `performance-m1-isolated-test-v1` / `reports` / `demo/current`에 사진(Data URL), 설비별 점검값, 측정값 및 사유를 저장합니다.
- M1.3.0 이후 계정별 IndexedDB `performance-m1-account-<Supabase User ID>`로 저장 경로가 변경되어, 이전 자료가 자동으로 나타나지 않습니다.
- 새로운 Supabase `pjt_performance_test_docs_v1` 테이블은 실제 조회 기준 아직 문서 0건입니다. 새 테이블 생성만으로 이전 브라우저 자료가 이동하지 않습니다.

## 복구 방법
1. 이전 사진·측정값을 입력했던 **원래 PC/휴대폰 및 원래 브라우저**로 접속하세요. GitHub Pages는 같은 도메인/포트/프로토콜의 폴더 간에 IndexedDB를 공유하므로 같은 출처에서 이전 저장공간에 접근할 수 있습니다.
2. M1.3.2에 통합 계정으로 로그인 후 점검표 화면의 `이전 버전 점검자료 복구` > `이전 자료 찾기`를 누르세요.
3. 발견한 설비/사진 수를 확인하고 반드시 `이전 자료 JSON 백업`을 다운로드하여 실제 파일이 저장되었는지 확인하세요.
4. 현재 계정의 점검표가 **비어 있고 클라우드 문서가 연결되지 않은 경우에만** `현재 계정에 복구`를 누르세요. 기존 브라우저 DB는 삭제/수정하지 않습니다.
5. 사진과 측정값을 먼저 확인한 후, 원하는 경우 `이 기기 자료 클라우드에 올리기`로 처음 클라우드에 등록합니다. 사진이 많으면 전체 JSON 24MB 제한 및 DB 타임아웃이 발생할 수 있으므로 백업을 우선 보관합니다.
6. 다른 브라우저/기기에서는 이전 저장공간에 접근할 수 없습니다. 그 경우 구 버전에서 `테스트 JSON 백업`을 다운로드하여, 새 버전의 `백업 불러오기`를 사용하세요. 기존 자료 덮어쓰기에 유의하세요.

## 안전성
- 자동 클라우드 업로드, SQL 수정, 기존 IndexedDB 삭제 없음.
- 사용자가 직접 이전 자료 찾기/백업/복구를 선택합니다.
- 현재 계정에 작성자료가 있거나 클라우드 동기화가 활성화되면 복구를 차단합니다.
- 기존 똑띠i와 영업/점검 관리 데이터는 변경하지 않습니다.
- 동일 브라우저라도 시크릿 모드/사이트 데이터 삭제/브라우저 프로필 변경 시 이전 자료가 보이지 않을 수 있습니다.
- 같은 계정 전체의 여러 점검현장을 자동으로 병합하는 기능은 아닙니다. 기존 `demo/current` 문서 한 개를 복구합니다.
