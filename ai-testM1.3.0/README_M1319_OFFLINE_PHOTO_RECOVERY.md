# 똑띠체크 M1.3.19: 오프라인 점검과 사진 원본 복구

## 변경 사항
- M1.3.18 기반. 기존 계정 권한·Supabase 테이블·사진 업로드 경로 및 `demo/current` 공유 문서 구조 변경 없음.
- 오프라인 웹 실행: 기존 Service Worker 캐시 유지 및 새 원본 사진 보관함 스크립트 추가. 최초 온라인에서 로그인 및 체크리스트 열기 필요.
- 오프라인 점검·사진·측정값: 기존 IndexedDB 보고서/업로드 대기 트랜잭션과 온라인 복구 자동 재전송 유지. 브라우저를 닫았다면 다시 열어야 업로드가 시작될 수 있음.
- **추가 보호**: 점검표 카메라/갤러리로 첨부한 사진 원본 File을, 기존 점검표와 다른 IndexedDB `ttoktti-original-photo-vault-v1`에 보관한 후 이미지 축소·첨부·저장을 실행. 보관 실패 시 원본 보존 실패를 알리고 첨부를 중단.
- 점검표 상단 **이 기기의 원본 사진 보관함**에서 저장된 원본을 찾아 공유/내보내기. 내보낸 사진을 휴대폰 사진 앱/파일에 저장한 후 점검표의 `사진 선택 · 갤러리 / 파일`로 다시 첨부 가능.
- 기존 사진 첨부 UI, CH-2 선택 화면 유지, PC·모바일 클라우드 저장 및 비공개 Storage 업로드 경로는 그대로 유지.

## 웹 플랫폼의 중요한 제한
- iOS Safari 및 인앱 브라우저에서 웹 앱이 권한 없이 촬영 사진을 iPhone의 **사진 앱**에 직접 자동 등록하는 것은 불가. 보관함 `사진 앱에 저장 / 내보내기`를 눌러 공유 시트의 `이미지 저장`을 사용하거나 수동 저장해야 함.
- Safari에서 파일 공유 기능이 지원되지 않으면 다운로드로 대체됨. 모바일의 `파일` 앱과 `사진` 앱은 서로 다름.
- OS가 웹 앱이 종료된 상태에서 백그라운드 업로드를 보장하지 않음. 연결 복구 후 앱을 다시 열고 `클라우드 저장 완료`를 확인.
- IndexedDB도 브라우저 데이터 삭제·사이트 저장공간 정리·용량 초과로 사라질 수 있음. **기기 내부 보관함은 사진 앱/외부 저장장치가 아니므로 유일한 백업으로 사용하면 안 됨.**
- 현재 기존 계정의 시험 문서 한 건만 공유. 여러 현장 자동 분리 불가.
- 새 버킷 SQL 실행 불필요. M1.3.17의 `ttoktti-test-photos` 버킷 및 권한 정책은 이미 설정한 상태로 사용.

## 검증 체크리스트 (실기기에서 수행 필요)
1. 온라인에서 M1.3.19을 실행하고 계정 확인 완료, 점검표 열기, JSON 백업.
2. 비행기 모드에서 페이지를 재진입해 점검표가 열리는지 확인. 열리지 않는다면 온라인에서 캐시 업데이트를 먼저 완료.
3. CH-2 사진을 촬영/첨부. 원본 사진 보관함의 목록에 CH-2 사진이 생성되는지 확인.
4. 오프라인에서도 새로고침 후 사진과 측정값이 보이는지 확인.
5. 온라인 복귀 후 앱을 다시 열어 **클라우드 저장 완료** 확인. PC의 동일 계정 CH-2 사진 확인.
6. 보관함에서 `사진 앱에 저장 / 내보내기` 누르기 → iPhone 공유 메뉴에서 `이미지 저장` 선택 → `사진` 앱의 사진 확인. 실패 시 해당 파일을 `파일` 앱에 저장.
7. 보관함에서 내보낸 사진을 `사진 선택 · 갤러리 / 파일`로 다시 첨부해 복구 확인.

## 제한된 검증
- JavaScript 정적 문법, 캐시 등록 항목, ZIP 무결성 검사 실시. iPhone 비행기 모드 및 Supabase 실제 전송 테스트는 아직 수행하지 않음.
