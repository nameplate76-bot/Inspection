# M1.2.7 클라우드 저장 시간 초과 대응

## 오류
`canceling statement due to statement timeout`은 Supabase PostgreSQL 문장이 제한 시간을 초과하여 취소되었다는 뜻입니다. AI 챗봇 로그인과 다른 기능입니다.

## 이번 변경
- 기존 전체 JSON 저장 방식과 DB 스키마, API 키, 점검표 데이터 구조는 변경하지 않았습니다.
- DB statement timeout 발생 시 2.6초 간격 무한 자동 재시도를 중지합니다.
- 클라우드 저장 실패를 완료로 표시하지 않으며, 로컬 자료의 JSON 백업 및 DB 확인을 안내합니다.
- 상단 '이 기기 자료 클라우드에 올리기'는 사용자가 백업과 원인 확인 후 수동 재시도할 수 있습니다. 덮어쓰기 확인이 나타날 수 있습니다.
- 브라우저에서 `PERFORMANCE_M1_CLOUD.debug()` 실행 시 `localBytes`, `syncPausedByTimeout`으로 상태 확인 가능(개발자 도구).

## 반드시 확인
1. 화면 상단 `테스트 JSON 백업`을 눌러 실제 파일을 확보합니다. 저장 실패 전후 작성한 내용도 포함되는지 확인합니다.
2. Supabase SQL Editor에서 해당 시험용 테이블의 크기, 관련 트리거, 정책, 느린 쿼리, DB 자원 현황을 확인해야 근본 원인을 진단할 수 있습니다.
3. 사진(data URL)을 전체 document JSON에 포함해 갱신하는 기존 구조는 이미지가 많아질 때 DB 타임아웃이 재발할 수 있습니다. 사진을 Storage로 분리하고 JSON을 현장/설비 단위로 나누는 작업은 별도 마이그레이션이 필요합니다.
4. 클라우드 미저장 상태에서는 다른 기기로 최신 자료가 전달되지 않습니다. 다른 기기에서 '클라우드 자료 불러오기'를 누르면 아직 올라가지 않은 변경사항이 사라질 수 있습니다.

이번 패치는 **타임아웃 재시도 폭주 방지와 데이터 보존 안내**이며, 서버의 느린 쿼리나 데이터 크기 문제 자체를 해결하는 패치는 아닙니다.
