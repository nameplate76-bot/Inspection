# 똑띠체크 M1.2.3 — GPT-6 Luna AI 테스트 배포 안내

## 실제 소스 검증 결과
- 기존 ZIP 안에 `AI_TEST_BILLING_SETUP.sql`, `supabase/functions/ttoktti-ai/index.ts`가 있습니다.
- 기존 소스는 `pjt_profiles`의 운영 포털 승인을 요구하므로 **빈 테스트 프로젝트에서 403 오류**가 발생합니다. 이 테스트 패키지에서는 독립 승인 테이블로 변경했습니다.
- 기존 `../supabase-config.js`는 업무포털 공유용이므로 변경하지 않습니다. AI는 `assets/ttoktti-ai-test-config.js`의 별도 설정을 사용합니다.
- 공식 똑띠체크 문자상표와 똑띠i 이미지 원본 및 기존 점검표 엔진은 변경하지 않았습니다.

## 순서 (반드시 테스트 프로젝트만)
1. 새 테스트 Supabase 프로젝트 `ttoktticheck-ai-test` (`axlrmgnwhybosblrvpay`)에서 **SQL Editor**를 열고 `AI_TEST_BILLING_SETUP.sql` 전체를 검토한 후 실행하세요. 운영 `pjt-progress`에서는 실행 금지. 승인 테이블 포함 4개 독립 테이블 및 2개 RPC를 생성합니다.
2. **Authentication > Users**에서 테스트 전용 이메일 계정을 생성하고 비밀번호를 지정하세요. 운영 계정과 별개입니다. 테스트 사용자 이메일/비밀번호를 채팅에 보내지 마세요.
3. 테스트 계정 UUID를 복사한 다음 SQL Editor에서 아래 SQL의 UUID를 교체해 실행하세요.

```sql
insert into public.ttoktti_ai_test_approvals_v1(user_id, approved)
values ('여기에-테스트-사용자-UUID', true)
on conflict (user_id) do update set approved = true;
```

4. **Edge Functions > Secrets**에서 이미 등록된 `OPENAI_API_KEY`, `TTOKTTI_ALLOWED_ORIGINS`(= `https://nameplate76-bot.github.io`)를 유지하세요. 선택적으로 `OPENAI_MODEL` = `gpt-6-luna`를 추가하세요. OpenAI 키의 Responses = Write를 확인하세요.
5. **Edge Functions > Functions > Via Editor**에서 Function name을 `ttoktti-ai`로 지정하고 `supabase/functions/ttoktti-ai/index.ts`의 **전체 코드를 붙여넣어 배포**하세요. 기본 Hello 예제는 사용하지 마세요. 인증/JWT 확인을 우회하지 마세요.
6. Supabase **Project Settings > API Keys**에서 이 **테스트 프로젝트**의 **publishable** 키(`sb_publishable_...`, 공개 클라이언트용)를 확인하여 `assets/ttoktti-ai-test-config.js`의 `PASTE_TEST_PROJECT_PUBLISHABLE_KEY_HERE`만 교체하세요. OpenAI 비밀키나 Supabase secret/service-role 키를 절대 넣지 마세요.
7. 운영 GitHub Pages의 `Inspection/performance`에 즉시 덮어쓰지 마세요. 별도 테스트 GitHub Pages 브랜치/저장소에 `performance` 폴더를 먼저 배포하세요. 다른 도메인에서 시험할 경우 `TTOKTTI_ALLOWED_ORIGINS`에 그 도메인의 Origin을 추가해야 합니다.
8. 테스트 웹페이지의 `checklist.html`을 열어 똑띠i 버튼을 누르고 **AI 테스트 전용 계정으로 로그인**하세요. 추천 질문은 로컬 FAQ이며 사용량이 증가하지 않습니다. 직접 질문만 모델 호출 및 사용량 예약을 실행합니다.
9. 승인 사용자/비승인 사용자/미로그인/월 30회·전체 1000회 제한/AI 오류/점검표 PDF·Excel·저장을 확인하세요. **미테스트이며 실제 API 호출 또는 비용 발생 검증은 하지 않았습니다.**

## 중요한 한계
- API 질문당 최대 250자, 출력 최대 450토큰, 사용자 월 30회, 전체 월 1000회 상한이지만 USD 지출 상한을 보증하지는 않습니다. OpenAI 크레딧 및 예산 알림은 별도로 관리하세요.
- 예제 테스트 승인 계정이 없으면 403이 정상입니다. 운영 업무포털 계정을 자동으로 가져오거나 복제하지 않습니다.
- 현재 AI는 입력한 질문 **텍스트만** 외부 모델에 보냅니다. 점검표의 데이터와 사진을 자동 전송·수정하지 않습니다.
- `ttoktti-ai` function의 인증은 서버 내부에서 `auth.getUser`로 검증합니다. 외부 직접 호출까지 CORS만으로 차단하지는 못합니다.
- SQL의 `SECURITY DEFINER` RPC는 service_role만 호출 가능하도록 권한을 제한합니다. 설치 후 Security Advisor 검사 및 테스트가 필요합니다.
- 차후 운영 배포 전에는 미완료 예약 정리, 비용 상한, 입력 필터링, 감사 로그, OAuth/JWT 정책, 관리자 승인 UI를 별도 보완해야 합니다.
