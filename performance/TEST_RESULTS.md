# M1.0.3 시험 결과 (2026-11-09)

## 검증 완료

- 기존 M1.0.2에서 수정한 27종 점검항목/출력 엔진 파일 유지
- JavaScript 구문검사 통과: `cloud-sync.js`, `legacy-checklist-engine.js`
- 격리된 Chromium 모의 Supabase 서버 시험: 승인 계정 감지, 최초 업로드(Revision 1), 원격 변경 반영(Revision 2), 로컬 변경 자동 업로드(Revision 3), 수정 충돌 자동 덮어쓰기 차단 통과
- 두 번째 브라우저 컨텍스트(동일 승인 계정, 빈 로컬 저장소): 클라우드의 설비·현장정보 자동 불러오기 통과
- 모바일 390px 화면 렌더링 및 가로 스크롤 없음, 로컬 모드 오류 없음
- 실제 Supabase 프로젝트 `spkxyjmtbcnkxafrksao`의 **신규 전용 테이블** `public.pjt_performance_test_docs_v1` 설치 결과: RLS 활성화, 정책 3개, Realtime 등록, 0개 행
- `anon` 역할의 SELECT/INSERT 권한 없음. 인증 역할은 SQL 권한이 있더라도 RLS를 통과해야 실제 데이터를 조회 가능

## 검증하지 못한 항목

- 실제 사용자의 Supabase 이메일/비밀번호로 PC와 휴대전화 두 기기에서 로그인하는 시험
- 실제 무선 네트워크/휴대전화에서 사진을 포함한 대형 보고서 업로드·다운로드 및 백그라운드 동기화
- 두 명 이상의 서로 다른 직원 계정 사이의 공동편집 (이번 버전 지원 대상이 아님)
- 전체 27종 PDF·Excel 원본양식 동일성 재검증 (이번 수정 범위 제외)

## 데이터 보호

- `pjt_records`, `pjt_shared_state`, 기타 업무포털 테이블 및 기존 점검표 데이터 변경 없음
- 신설 테이블은 시험용 0건으로 시작하며 각 `owner_id` 본인 자료만 읽고 변경하도록 제한
- 이미 PC 브라우저에 있던 로컬 M1 데이터를 유지하며, 최초 클라우드 업로드/덮어쓰기는 사용자가 명시적으로 선택
- 브라우저 CDN 장애 또는 로그인 불가 시 로컬 저장 모드로 유지

## 제한 사항

사진은 이번 단계에서 본문 JSON 안의 데이터 URL로 클라우드에 저장됩니다. 전체 문서가 24MB보다 커지면 클라우드 저장을 중지하고 로컬 데이터를 유지합니다. 실서비스 전에는 현장·설비별 문서 분리 및 전용 Storage 사진 보관 구조를 구현해야 합니다.
