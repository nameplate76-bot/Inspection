# 똑띠체크 M1.1.4 — GPT-6 Luna 테스트 결제·크레딧 연결 안내

## 현 상태 및 꼭 알아둘 사항
- 전체 기능 소스와 설치 파일을 포함하였지만, **실제 OpenAI 결제·Supabase SQL 설치·Edge Function 배포는 자동으로 실행하지 않았습니다.**
- **테스트 기본형: 월 기본료 0원(상품 모델의 시뮬레이션용 표시)**, 계정당 월 AI 질문 30회, **전체 승인 사용자 합산 월 1,000회**입니다.
- 추가 크레딧은 `credit_allowance` 항목으로 관리합니다. **현재 온라인 결제·자동충전·카드 청구가 연결되지 않았습니다.** 실결제 후 검증 전까지 유상 크레딧을 자동 추가하지 마세요.
- AI 답변에 쓰는 모델 ID는 `gpt-6-luna`이며, 직접 입력한 질문은 Edge Function을 통합니다. 추천 질문 버튼은 로컬 FAQ이므로 API 사용량을 소모하지 않습니다.
- 월 구분은 **한국시간(KST)** 기준입니다. 월이 바뀌면 신규 사용량 집계가 만들어집니다. 남은 크레딧은 해당 월에만 유효한 설계입니다.
- **테스트용 Supabase 프로젝트**에서만 아래 단계를 먼저 확인하고, 운영 환경의 기존 테이블 및 권한을 절대 변경하지 마세요.

## 설치 순서 — DB SQL은 자동 실행되지 않음

### 1) 백업 및 테스트 프로젝트 확인
- 기존 운영 프로젝트는 그대로 유지하고 테스트/스테이징 프로젝트에서 검증하세요.
- 프로젝트에 기존 `pjt_profiles` 승인 정보와 로그인 계정 구조가 있어야 합니다. 완전 신규 테스트 프로젝트라면 별도로 승인 계정/권한 데이터를 준비해야 합니다.
- 현행 `../supabase-config.js`의 URL 및 공개용 anon/publishable 키가 **테스트 프로젝트**를 가리켜야 합니다. 비밀키는 그 파일에 넣지 않습니다.

### 2) 별도 테이블 생성
- Supabase 대시보드 → 테스트 프로젝트 → SQL Editor에서 `AI_TEST_BILLING_SETUP.sql` 내용을 검토하고 **테스트 프로젝트에서만** 실행합니다.
- 새 테이블: `ttoktti_ai_monthly_global_v1`, `ttoktti_ai_monthly_users_v1`, `ttoktti_ai_requests_v1`.
- 새 RPC: `ttoktti_ai_reserve_v1`, `ttoktti_ai_finish_v1`. 함수 EXECUTE 권한은 service_role에만 부여, 사용자에게 사용량 변경 권한 없음.
- 기존 점검표 테이블과 기존 운영 포털 테이블의 데이터/구조를 변경하지 않습니다.

### 3) OpenAI API 별도 결제 설정
1. https://platform.openai.com/ 에 로그인합니다. ChatGPT 구독과 API 과금은 **별도**입니다.
2. API Billing에서 카드 등록 후 선불 크레딧을 구매합니다. 일반적인 최소 충전액은 **$5**입니다.
3. 테스트 동안은 **Auto-recharge(자동충전)를 OFF**로 유지하세요. API Project의 사용량/예산 알림도 별도로 확인하세요.
4. API Keys에서 이 프로젝트 전용 API 키를 발급합니다. 키는 **대화창·GitHub·문서·웹 코드에 붙여넣지 마세요.**
5. Supabase → 테스트 프로젝트 → Edge Functions → Secrets에 `OPENAI_API_KEY`로 저장하세요.
6. `TTOKTTI_ALLOWED_ORIGINS`에는 페이지를 제공하는 출처(origin)를 쉼표 구분으로 입력합니다. 예: `https://example.github.io` (경로 `/repo/performance` 는 넣지 않음). localhost 테스트가 필요하다면 해당 origin을 별도로 추가합니다.

### 4) Edge Function 배포
- `supabase/functions/ttoktti-ai/index.ts` 코드를 테스트 프로젝트의 `ttoktti-ai` Edge Function에 배포하세요.
- Supabase 대시보드에서 Edge Functions → Deploy a new function → Via Editor로 파일 내용을 붙여 넣어 배포할 수 있습니다.
- CLI를 사용하는 경우 프로젝트 연결 후 해당 이름의 함수를 배포할 수 있습니다. 공식 문서: https://supabase.com/docs/guides/functions/deploy
- 기존 Supabase `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`는 Edge Function의 서버 환경에서 읽습니다. 서버 측에만 보관하세요.
- **로그인 인증을 사용하는 상태로 배포**합니다. 인증 검증을 비활성화하여 우회하지 마세요.

### 5) GitHub 페이지 적용
- ZIP의 `performance/` 내용으로 해당 폴더만 업데이트합니다.
- 원본 캐릭터·문자상표, 기존 성능점검 엔진, PDF/Excel, Supabase 점검표 동기화 파일은 변형하지 않았습니다.
- 점검표로 이동하여 상단 PC·모바일 공유에서 승인 계정으로 로그인한 뒤 오른쪽 아래 똑띠i를 클릭합니다.
- 추천 질문은 내장 FAQ, 직접 질문은 Luna API를 사용합니다.

### 6) 반드시 수행할 검증
1. 로그인하지 않은 상태 → AI 요청이 차단되어야 합니다.
2. 승인되지 않은 사용자 → 차단되어야 합니다.
3. 승인 계정 → 직접 질문 시 AI 답변이 표시되고 사용량 1건 증가해야 합니다.
4. 추천 FAQ → 사용량이 증가하지 않아야 합니다.
5. 계정별 월 30건 이후 → 추가 크레딧이 없는 계정은 차단되어야 합니다.
6. 전체 월 1,000건 이후 → 사용자 추가 크레딧이 있더라도 추가 API 요청은 차단되어야 합니다.
7. 브라우저의 X/캐릭터 버튼으로 닫았다 열면 초기 도움말 화면이 나타나야 합니다.
8. 기존 PDF·Excel 출력, 사진, 점검표 저장/동기화가 동작하는지 반드시 테스트해야 합니다.

## 운영자 수동 테스트 크레딧 추가
- 관리자가 테스트 프로젝트에서 직접 승인된 사용자 계정과 월을 확인한 뒤, `ttoktti_ai_monthly_users_v1.credit_allowance`를 증가시킬 수 있습니다.
- **사용자가 구매 버튼을 눌러 크레딧이 자동 반영되지는 않습니다.** 실제 상용결제 연동 전에는 은행/PG 결제 확인 후 기록해야 합니다.
- 전체 월 1,000건은 별도의 상한이므로 크레딧을 부여해도 전체 한도를 넘길 수 없습니다.
- 정식 출시 전에는 검증된 PG 웹훅, 결제/환불 원장, 조직별 구독 및 사용량 정책, 만료 정책, 과금내역 조회 기능을 추가해야 합니다.

## 장애/보안 유의점
- CORS 허용 origin을 설정하지 않으면 API 요청이 거절됩니다(안전한 기본값).
- 서버 설정을 완료하지 않은 상태에서는 직접 질문 시 오류와 관련 FAQ를 보여주고, 기존 점검표 작업은 계속 가능합니다.
- API 호출에 실패하면 서버는 사용량 예약을 되돌리도록 구성했습니다. 다만 서버 장애나 외부 과금이 이미 발생한 비정상 상황에서는 차이가 생길 수 있으므로 운영 시 정산/조정 도구가 필요합니다.
- OpenAI로 전송되는 것은 질문 문장뿐입니다. 점검표 전체와 사진은 자동으로 전송하지 않습니다.
- 개인정보·현장 민감정보를 질문에 넣지 말고, 향후에는 전송 전 익명화/로그 정책을 별도로 마련하세요.
